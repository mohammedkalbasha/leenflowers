# مواصفات تصميم وتطوير المرحلة الثانية: متجر لين للزهور (Leen Flowers - Phase 2)

**التاريخ:** 2026-10-03  
**الحالة:** معتمد  
**المشروع:** ربط قاعدة بيانات دائمة، REST API، حماية لوحة التحكم برمز PIN، تسجيل الطلبات تلقائياً، وإصدار بطاقات الإهداء وفواتير التوصيل للطباعة.

---

## 1. أهداف المرحلة الثانية (Phase 2 Goals)

1. **قاعدة بيانات مدمجة دائمة (SQLite Database):**
   - استخدام محرك `node:sqlite` المدمج في Node.js 25 بدون أي حزم خارجية أو تبعيات تثبيت إضافية.
   - حفظ المنتجات، الطلبات، إعدادات المتجر، والرموز السرية في ملف قاعدة بيانات موحد `data/leen_flowers.db`.
   - الترحيل التلقائي (Auto Seed) للمنتجات والإعدادات الافتراضية عند التشغيل لأول مرة.

2. **واجهة برمجية كاملة (REST API):**
   - نقاط نهاية (Endpoints) للمنتجات: `GET, POST, PUT, DELETE /api/products`.
   - نقاط نهاية للطلبات: `GET, POST /api/orders`، وتعديل الحالة `PUT /api/orders/:id/status`.
   - نقاط نهاية لإعدادات المتجر: `GET, PUT /api/config`.
   - نقطة نهاية للإحصائيات الحقيقية: `GET /api/stats`.
   - التحقق من الرمز السري: `POST /api/auth/login`.

3. **حماية لوحة التحكم (Admin PIN Protection):**
   - قفل لوحة التحكم `dashboard.html` بـ PIN كود افتراضي `1234`.
   - إمكانية تغيير الرمز السري من داخل إعدادات اللوحة.
   - منع الزوار غير المصرح لهم من رؤية بيانات العملاء أو التعديل على المنتجات والأسعار.

4. **التكامل المزدوج للطلبات (Database + WhatsApp):**
   - عند إتمام الطلب من واجهة المتجر `index.html`:
     - يتم حفظ الطلب رسمياً في قاعدة البيانات وحجز رقم تسلسلي أنيق للطلب (مثل: `LF-26-001`).
     - يتم توليد رسالة الواتساب المتضمنة رقم الطلب وتوجيه المشتري كالمعتاد.
     - استمرار عمل المتجر بنظام Fallback التلقائي في حال تم فتح الموقع بدون خادم محلي (`file://`).

5. **نظام طباعة كرت الإهداء وإرسالية السائق ومُنسّق الزهور (Print Slips):**
   - إضافة زر `[ 🖨️ طباعة ]` بجانب كل طلب في لوحة التحكم.
   - توليد قسيمة طباعة مخصصة عالية الجودة بنظام `@media print` مقسمة إلى:
     - **كرت الإهداء الفاخر (Gift Card):** إطار وردي أنيق وجاهز للقص والإرفاق مع الورد.
     - **بيانات التجهيز لمنسق الزهور (Florist Slip):** نوع الورد، العدد، التغليف، والملاحظات الخاصة.
     - **إرسالية السائق (Delivery Slip):** اسم المستلم، الهاتف، العنوان، موعد التوصيل، والمبلغ المطلوب تحصيله.

## 2. الهيكلية وتوزيع الملفات (File Architecture)

```text
flower/
├── data/
│   └── leen_flowers.db         # ملف قاعدة البيانات SQLite
├── server.js                   # خادم HTTP المدمج مع REST API و Database
├── js/
│   ├── api-client.js           # عميل API خفيف موحد للمتجر ولوحة التحكم
│   ├── store-config.js         # إعدادات المتجر مع تكامل API
│   ├── products-data.js        # جلب وحفظ المنتجات عبر API مع Fallback محلي
│   ├── dashboard.js            # لوحة التحكم المحمية بالرمز وإدارة الطلبات والطباعة
│   └── app.js                  # واجهة المتجر مع إرسال الطلبات إلى API
├── css/
│   ├── main.css                # تحسينات التصميم وأنماط نافذة الطباعة والقفل
│   └── print.css               # أنماط الطباعة المخصصة للكرت والإرسالية
├── dashboard.html              # لوحة التحكم مع شاشة القفل ومودال الطباعة
└── index.html                  # المتجر الرئيسي مع عرض رقم الطلب
```

## 3. معايير القبول والتحقق (Acceptance Criteria)
1. تشغيل `server.js` بنجاح وإنشاء `data/leen_flowers.db` تلقائياً مع 8 منتجات مبدئية.
2. كافة نقاط نهاية REST API تعمل وتستجيب بصيغة JSON مع معالجة الأخطاء.
3. فتح `dashboard.html` يطلب الرمز السري `1234` قبل السماح باستعراض البيانات.
4. إجراء طلب من المتجر يؤدي إلى ظهوره فوراً في جدول طلبات لوحة التحكم.
5. النقر على زر الطباعة في لوحة التحكم يفتح معاينة الطباعة لكرت الإهداء وإرسالية السائق بدقة وتنسيق بدون أي عناصر إضافية.
6. اجتياز كافة الاختبارات الآلية الجديدة بنسبة 100%.
